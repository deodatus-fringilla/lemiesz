## 1. Why This Exists

An AI model can produce arguments at scale, but public advocacy requires human accountability. Pakt Lemiesza operates on three distinct trust tiers:
1. `human_approved`: Manually vetted by an authenticated reviewer.
2. `ai_verified`: Drafted and audited by independent AI models, awaiting human sign-off.
3. `draft` / `flagged` / `stale`: Incomplete, contested, or invalidated cards.

If an unapproved draft or a stale card leaks into an official press release or social media thread generated by the Content Engine, the movement speaks without human authorization.

---

## 2. Invariant Rules

1. **Default Export Exclusion:** By default, all Content Engine generation queries (`getArgumentsForTopic()`) MUST filter with `status = 'human_approved'`.
2. **Watermark Enforcement on Override:** If a user explicitly checks *"Include unverified drafts"*, the output generator must prepend a bold watermark:
   `⚠️ DRAFT CONTENT: Contains unapproved AI arguments. Not authorized for public release.`
3. **Stale Cascade on Source Edit:** If an editor modifies the text or translation of a source in the Repository, all dependent argument cards MUST immediately have their status flipped from `human_approved` or `ai_verified` to `stale`.
4. **Session Actor Attribution:** Review approval status can never be passed in the request payload; it must be extracted strictly from the validated server session (`locals.user.id`).

---

## 3. Proof It Can Fail

- **Negative Control:** Seed the database with 3 cards: 1 `human_approved`, 1 `ai_verified`, 1 `draft`. Query the Content Engine export endpoint without override flags.
- **Assertion:** The returned card count is strictly 1. Attempting to pass `status: 'human_approved'` in an unauthenticated or non-admin POST request returns HTTP 403 Forbidden.
